# SBGA TOOL（songs）

maimai DX / CHUNITHM / オンゲキ 三个游戏的曲目资料（只有曲目和谱面信息，没有成绩）。一个网页，顶部切换游戏。

**网址：[https://131a562.github.io/sbga-tool/](https://131a562.github.io/sbga-tool/)**（数据每天日本时间 3:00 自动从各数据库重新获取）

## 打开方式

- **网页版（推荐）**：手机、电脑用浏览器打开 [https://131a562.github.io/sbga-tool/](https://131a562.github.io/sbga-tool/) 就能用（部署方法见下面「部署」）。
  - iPhone：用 Safari 打开 →「分享」→「添加到主屏幕」，之后从主屏幕打开就和 App 一样全屏显示。
  - 安卓：Chrome 打开 → 菜单 →「添加到主屏幕 / 安装应用」。
  - 第一次打开后，网页和三个游戏的数据都会缓存在手机里，没网也能查；看过的曲绘也会缓存（最多 800 张）。数据更新后，下次打开会在后台下载，再下一次打开就是新的。
- **本地**：直接双击 `index.html` 也能用（离线缓存只在网址打开时有效）；或者 `node scripts/serve.mjs` → [http://localhost:5190/](http://localhost:5190/)

## 部署（GitHub Pages）

1. 在 GitHub 新建一个仓库（例如 `sbga-tool`），把这个文件夹（`songs/`）的内容作为仓库根目录推上去。`.gitignore` 排除了本地的 `app/` 文件夹（以前试做的安卓 App，已不再维护，里面有签名密钥和用 SEGA 角色图做的图标素材）。
2. 仓库 Settings → Pages → Build and deployment → Source 选 **GitHub Actions**。
3. 到 Actions 页面运行一次「更新数据并部署」（之后每次推送和每天日本时间 3:00 会自动运行）。
4. 几分钟后打开 `https://<用户名>.github.io/<仓库名>/`（现在的仓库是 [131a562/sbga-tool](https://github.com/131a562/sbga-tool)，网址 [https://131a562.github.io/sbga-tool/](https://131a562.github.io/sbga-tool/)）。

工作流（`.github/workflows/deploy.yml`）每次都会重新下载数据再部署，所以网页上的数据每天自动更新，不用手动运行 `build-data.mjs`。生成的新数据只发布到网页上，不会提交回仓库，所以仓库里的 `data/` 一直是最后一次手动推送的那一版；某个数据源连不上时就用它部署，网页照常能打开。

改了网页的文件列表（新增文件等）或缓存策略时，把 `sw.js` 里的 `VERSION` 加 1。

## 条目怎么算

- **maimai**：同一首歌的「标准」谱和「DX」谱是两个条目，各有自己的版本（例如老歌的 DX 谱算在追加它的版本里）。每个宴谱（`[宴]` `[協]` 等）是单独的条目，双人宴谱分左右两份物量和容错。
- **CHUNITHM**：每个 WORLD'S END 谱面是单独的条目（`WE·狂` 等），和同名的通常曲分开。
- **オンゲキ**：LUNATIC 条目尽量合并回原曲，作为原曲的一个难度：原曲的 Re:MASTER（43 个现行 + 9 个已删除）→ 原曲的 Re:MASTER 难度，哪个是 Re:MASTER 按 Tachi 的分类，和 wikiwiki「楽曲一覧」的 Re:MASTER 一览（43 个）完全一致；其余等级不是 0、并且有曲名和艺术家都一样的通常曲的 LUNATIC（9 个，初音ミクの激唱、MEGALOVANIA 等）→ 原曲的 LUNATIC 难度。等级为 0 的 LUNATIC（25 个）和没有通常曲的 LUNATIC 专用曲（14 个）仍是单独的条目。原曲里已删除的谱面标「已删除」，只在「全部（含已删除）」里算。
- 卡片页的「同名的其他条目」可以在这些条目之间跳转。

## 筛选

- **曲名**：「模糊」不分全角半角、大小写、片假名平假名、浊点、小字、长音和符号，搜读音也行（`せんぼんざくら` → 千本桜），也可以用罗马音搜假名和汉字（`senbonzakura`、`ragutorein`；平文式、训令式都行，长音写 `-` 或省略，如 `sama-taimu` / `samataimu`）。汉字靠读音匹配，所以和读音一样，只在曲名没有空格时能用罗马音搜到汉字。关键词必须作为连续的字出现在曲名的同一个单词里，不会拆开，也不会跨过曲名里的空格（`oshma`、`oshamascramble` 都搜不到 Oshama Scramble!）；读音只在曲名没有空格时参与匹配（艺术家、谱师同样按单词）；关键词中间有空格时按空格分成几个词，每个词都要出现（顺序不限，`scramble oshama` → Oshama Scramble!）。从开头就对上的排前面。「正则」不是通用的正则表达式，只有两个特殊符号：`_` 表示一个不是空格的字符，`*` 表示一个以上不是空格的字符，其他字符都按原样匹配（例：`o__ma` = o、两个非空格字符、ma；`love*song` = love 和 song 中间至少有一个非空格字符，跨不过空格）。可以匹配在曲名中间任何位置，不分大小写、全角半角。也会对读音匹配，但读音是连在一起写的（On your mark → ONYOURMARK…），所以曲名里有空格时只匹配曲名，不会通过读音跨单词匹配。旁边可以把搜索对象换成艺术家或谱师。
- **定数**：填最低 / 最高（只填一头也行），只看选中「难度」的谱面。定数还没公开的谱面勾了「未公开的按等级估」时按等级算（13+ ≈ 13.7），卡片上显示 `?`。宴谱 / WORLD'S END 没有定数。
- **难度**：没填定数时，只留下有选中难度谱面的曲目（例如只选 Re:MASTER = 有 Re:MASTER 的曲目）。
- **版本**：可多选，「只看最新版本」一键选当前版本。
- **服务器**（maimai：日服 / 国际服 / 国服；中二：日服 / 国际服 / 国服；音击只有日服）：只看这个服务器现在有的曲目，**定数、等级、版本也按这个服务器**——定数筛选、排序、列表上的定数、卡片页的 Rating 都跟着变。国服的版本是国服自己的名字（舞萌DX 2024 等），切换服务器时版本筛选会清空。「全部（含已删除）」包含已删除的曲目，用日服的值（日服没有的谱面用国服的）。
- **对手**（只有音击）：按对战对手（敌方角色）筛选，下拉框按曲目数从多到少排，括号里是曲目数。
- 还有种类、分类、排序（定数 / 物量排序按符合条件的谱面里最高的那个）。
- 筛选条件按游戏记在这个浏览器里（搜索词除外）。

## 我的成绩

可以接入三个查分书签（chuni-b50 / maimai-dx-score / ongeki-score-export）同步到 otoge-history 的成绩记录，经由 otoge-sync **只读**取得（和 otoge-dashboard 用的是同一份数据）。

- **账号**：筛选面板的「账号」填同步名字（书签第一次同步时填的名字，大小写、全角半角都可以），点「读取成绩」。名字按游戏分别记在浏览器里；没填过时默认用 otoge-dashboard 记住的名字（同一个网站），所以用过查分面板的话打开就会自动读取。
- **显示**：只在卡片页的谱面卡里显示（列表和难度按钮上不显示），多一行「我的成绩」：最佳分数、评级、灯（maimai 还有 SYNC 和 DX 分 / 现在的 ✦ 数，音击还有 FULL BELL 和プラチナスコア / 星级），以及离下一个评级还差多少。
- **灯**：可以选打过 / 没打过 / 未 FC（打过、没有灯）/ 某一种灯（中二 FC / AJ / AJC，maimai FC / FC+ / AP / AP+，音击 FC / AB / AB+，选哪种就只留下灯正好是那一种的）。音击另外有 **FULL BELL**：FB / 未 FB。和定数、难度一样是按谱面算的：例如「MASTER + 定数 13.0〜13.9 + 灯 FC」= 有这样一张谱面的曲目。评级的范围用下面的「我的分数」筛（例如 SSS 但没到 SSS+）。
- **我的分数**：可以自己填分数范围（只填一头也行，两头都包含）。maimai 填达成率（例 `100` 〜 `100.4999`，不用写 %），中二 / 音击填分数（例 `1005000` 〜 `1007499`，可以带逗号）。只留下打过、最佳分数在范围内的谱面，和其他条件一起按谱面算。
- **排序**：「我的分数」按符合条件的谱面里定数最高那张的成绩排。
- **最佳成绩**：每个谱面取记录里分数最高的一次，灯取记录里最好的一次（和书签一样由观测记录重放得出）。
- **对不上的**：状态栏会写有几个谱面对不上曲目数据（鼠标停在上面能看到是哪些），一般是曲名写法不同或数据库里还没有的新曲。音击的 LUNATIC 记录会先对到原曲的 Re:MASTER / LUNATIC 难度，再对到单独的 LUNATIC 条目；分不出版本的游玩（书签记成「版本未知」）不算。
- **只能用网址打开**：同步服务只允许网站 `https://131a562.github.io` 读取，双击打开的本地文件、`localhost` 的本地预览会被浏览器拦下，状态栏会提示「本地打开时读不到成绩」。
- 本地测试可以加 `?sync=http://localhost:端口` 指到模拟的同步服务（只接受 localhost）。

## 卡片页

曲绘、读音、艺术家、分类、版本、BPM、实装日期、收录地区（音击只有日服，不显示）、wiki 链接、备注（宴谱的说明等）；音击还有对手（属性、敌人 Lv）和章节。

谱面信息上方是难度选项条（BASIC … MASTER / Re:MASTER / ULTIMA / LUNATIC / 宴 / WORLD'S END，按钮上写着定数或等级），点哪个难度就显示哪个难度的谱面卡，**默认选中最高难度**。所选服务器没有的谱面，按钮会变淡。每张谱面卡（所有难度都有）：各服务器的定数（并排显示，和当前服务器不同的标成橙色；所选服务器没有这个谱面时标「未实装」）、谱师、物量（总数和各种类）、SSS / SSS+ 的容错、单曲 Rating；音击还有白金分。

容错 = **只出这一种失误时最多能出几个**，其余全部最高判定：

| 游戏 | SSS+ / SSS | 容错按什么数 | 计算 |
|---|---|---|---|
| maimai | 100.5% / 100.0% | TAP GREAT、TAP GOOD（绝赞 50落 直接写每个扣多少 %） | 基础 100% 按 TAP·TOUCH 1、HOLD 2、SLIDE 3、BREAK 5 的权重平分；绝赞奖励 1% 按 BREAK 数平分。TAP GREAT −0.2 权重，GOOD −0.5；50落（2550）奖励只剩 75% |
| CHUNITHM | 1,009,000 / 1,007,500 | JUSTICE、ATTACK | 1,010,000 按物量平分，JUSTICE 少 1/101，ATTACK 少 51/101 |
| オンゲキ | 1,007,500 / 1,000,000 | BREAK、HIT、漏 BELL | 判定 950,000 按物量平分（BREAK 90%、HIT 50%）+ BELL 60,000 按 BELL 数平分；假设无被弹 |

单曲 Rating：maimai SSS+ = ⌊定数 × 22.4 × 1.005⌋、SSS = ⌊定数 × 21.6⌋；中二 SSS+ = 定数 + 2.15、SSS = 定数 + 2.00；音击按 Re:Fresh 的规则（和 Tachi 的实现一致）：SSS+ = 定数 + 2.05、SSS = 定数 + 1.45，另有灯加成 FULL BELL +0.05、FC +0.1、AB +0.3、AB+ +0.35，理论值 = 定数 + 2.7。定数是估的或参考值时前面加 `≈`。

maimai 另外显示 DX 分的 ✦1〜✦5 各需要多少分（理论值 = 物量 × 3，分别要 85% / 90% / 93% / 95% / 97%）。

音击另外显示 Re:Fresh 的プラチナスコア：理论值 = 物量 × 2，★1〜★5 / 虹★ 分别要理论值的 94%〜99%，★5 的星级 Rating = ⌊5 × 定数²⌋ ÷ 1000。

中二和音击的谱面卡上有 sdvx.in 的「谱面确认」链接。

## 更新数据

```bash
node scripts/build-data.mjs
```

下载三个数据源，合并后写到 `data/maimai.js` `data/chunithm.js` `data/ongeki.js`（各 1–2 MB）。新版本 / 新曲出来后跑一次就行。

- 主数据：[arcade-songs](https://arcade-songs.zetaraku.dev/)（zetaraku）— 曲目列表、每个谱面的版本、定数、谱师、物量、收录地区
- 补充：[otoge-db](https://otoge-db.net/)（zvuc）— 宴谱 / WORLD'S END / LUNATIC 的物量和谱师、各种类物量、读音、wiki 链接、音击角色等。按「曲名 + 艺术家」（再不行按曲名）对上
- 国服：[落雪查分器](https://maimai.lxns.net/)（LXNS）— maimai / 中二的国服收录、国服定数、国服版本；日服数据源缺的谱师和物量也用它补（主要是 WORLD'S END）。定数和水鱼查分器的一致（2026-10-21 对比过：中二全部一致，maimai 只有宴谱的写法不同）。国服有、日服数据里没有的曲目会单独加成条目（曲绘用落雪的）
- 音击参考定数：[Tachi](https://github.com/zkldi/Tachi) 的谱面库（`db/seeds/charts-ongeki.json`）。Re:Fresh Act.2 又改过一次定数，Tachi 的值是之前的，所以只用来补现行定数还没测出来的谱面，而且只在 Tachi 的等级和现在的官方等级一样时才用；卡片页标「参考，未确认」，列表上显示 `~10.7`；LUNATIC 里哪些是原曲的 Re:MASTER 也按 Tachi 的分类
- 国际服：maimai 用 arcade-songs 里国际服和日服不同的等级 / 定数 / 版本；中二没有国际服单独的数据，卡片页上国际服的定数是日服的值，带 `*` 标注
- 落雪的服务器在国内，从海外连偶尔超时，脚本会自动重试 3 次
- 调试时可以把各数据源的 json 下载到一个目录（`z_maimai.json` / `maimai.json` / `lx_maimai.json` 这样命名），`node scripts/build-data.mjs <目录>` 离线生成

## 已知限制

- 新曲刚实装时数据源还没填，定数 / 谱师 / 物量会显示「未公开」「未知」，过几天重新生成数据就有了。
- 所有数据源都没有的：一部分 WORLD'S END 和宴谱的物量，这些谱面算不了容错。
- 缺谱师的谱面（2026-10-21 统计，EXPERT 以上、现在还能玩的）：maimai 0 个；音击 8 个，全是 2026 年 10 月的新曲；中二 38 个——5 个是 10 月新曲，16 个是 2026-04-01 愚人节的 WORLD'S END，17 个是国服还没有的 WORLD'S END（中二的谱师主要靠落雪补，国服没实装的 WE 就查不到）。WORLD'S END 和日服新曲的谱师，等数据源更新后重新生成数据就会有。
- maimai 国服独有的曲目只有 arcade-songs 的数据（otoge-db 没有），没有读音和 wiki 链接。
- 中二国服的版本名用的是落雪的写法（和日服版本同名，如 CHUNITHM VERSE），不是国服宣传用的「中二节奏 2025」这种名字。
- 中二国际服的定数没有数据源，按日服显示（带 `*`）。
- 音击只在日本运营（没有国际服、国服），所以只有日服。
- 音击 EXPERT 有 75 个、LUNATIC 有 19 个谱面在哪个数据源都没有现行定数，只能按等级估。另外查过 OngekiScoreLog（ongeki-score.net，已确认的定数和现有数据完全一致，补不上新的）和 wikiwiki（很多页面还是 Re:Fresh 以前的定数）。
- 音击物量只有总数和 BELL，没有 TAP / HOLD / SIDE / FLICK 的细分（各数据源都没有）。
- 音击 Rating、白金分的规则来自 Tachi 的代码（注明「accurate as of Re:Fresh」），Act.2 有没有改过没有确认。
- オンゲキ LUNATIC 的「谱师」栏是数据源原样的文字（有些是谱面的说明）。
